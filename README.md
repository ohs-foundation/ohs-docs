# OHS Docs

Documentation site for the [Open Health Stack](https://ohs.foundation/) (OHS) project,
built with [Docusaurus](https://docusaurus.io/) 3.10 and published to
<https://ohs-foundation.github.io/ohs-docs/>.

It documents the components maintained under the
[ohs-foundation](https://github.com/ohs-foundation) organization — the Android FHIR SDK,
the Kotlin FHIR Multiplatform libraries, FHIR Gateway, FHIR Data Pipes, FHIR App Examples
— and the OHS Player reference toolkit that composes them.

## Layout

```
docs-content/          Markdown content; one directory per component
  index.md             site landing page (slug: /)
  ohs-player/          reference toolkit: overview, setups/, concepts/
  <component>/         index.md + _category_.json per component
src/
  components/ohs/      LandingPage, GuideShell, Brand — the site's own chrome
  theme/               swizzled Layout, DocItem/Layout, DocRoot/Layout
  css/custom.css       design tokens and all component styling
  data/repositories.js component key -> source repository label and URL
  assets/fonts/        self-hosted Hanken Grotesk and IBM Plex Mono
scripts/
  routes.json          canonical route contract
  check-routes.mjs     verifies the contract against content and build output
```

Docs are served from the site root (`routeBasePath: '/'`), so a page's URL is its path
under `docs-content/` — `docs-content/ohs-player/setups/client-app.md` becomes
`/ohs-docs/ohs-player/setups/client-app/`. The sidebar is autogenerated; ordering comes
from `sidebar_position` and `_category_.json`.

## Page contract

The site does not use the classic theme's navbar, footer, or doc layout. `src/theme`
replaces them with the shells in `src/components/ohs`, which read everything they render
from frontmatter:

| Frontmatter | Effect |
| --- | --- |
| `title` | `<h1>` and `<title>`. Pages must not repeat it as a body `#` heading. |
| `description` | Standfirst under the title, and the page's meta description. |
| `page_type: landing` | Renders `LandingPage` (hero + `eyebrow`, `primary_action`, `secondary_action`) instead of `GuideShell`. |
| `guide_type` | Label above the title, e.g. `Component`, `Setup guide`, `Concept`. |
| `guide_status` | STATUS field — whether a reader can act on the page today. |
| `guide_focus` | FOCUS field — what the page helps the reader do. |
| `repository` | Key into `src/data/repositories.js`; renders the source link. |

Adding a page therefore means adding Markdown and a `scripts/routes.json` entry. It does
not mean editing React or CSS. See [AUTHORING.md](AUTHORING.md) for the full contract.

## Local development

```bash
npm install
npm start
```

Serves the site at `http://localhost:3000/ohs-docs/` with live reload.

## Checks

```bash
npm run build      # onBrokenLinks and onBrokenMarkdownLinks are both 'throw'
npm run check      # route contract, frontmatter, and built output
npm run typecheck  # docusaurus.config.ts and sidebars.ts
```

`npm run check` requires a prior `npm run build`. It fails if a document is missing from
`scripts/routes.json` or vice versa, if a page's `title`/`description` drifts from the
contract, if a page reintroduces a body `#` heading, if a contracted route is not emitted,
if server-rendered output contains a React error, or if an internal link points at a page
the build did not produce.

Run both before opening a pull request. Neither runs in CI: the only workflow in this
repository is the deployment workflow described below.

## Deployment

`.github/workflows/deploy.yml` builds on every push to `main` and publishes `build/` to
GitHub Pages. Settings → Pages → Source must be set to "GitHub Actions" — a one-time
manual step, not part of this repository.

`url`, `baseUrl`, `organizationName`, and `projectName` in `docusaurus.config.ts` are tied
to that Pages site. Changing them repoints the deployment.
