QUICKSTART

Run the OHS Player reference client

Build and launch the Kotlin Multiplatform sample application that embeds the OHS Player runtime, then verify that its healthcare workflow loads.

20 min estimatedBeginner levelVerified 15 July 2026
i
What you will accomplish

You’ll clone the reference client, build its shared modules, run one platform target, and confirm the generated FHIR configuration is loaded.

✓

Before you begin

Install the requirements for your chosen target. Start with desktop if you want the shortest feedback loop.

✓

JDK 21Required for all targets

java -version
✓

Git 2.40+Used to clone the repository

git --version
+

Android Studio or XcodeOnly required for Android or iOS

OPTIONAL
1
STEP 1 OF 3

Clone the reference client

Clone the repository and change into its root directory. All remaining commands run from this directory.

TERMINAL
$ git clone https://github.com/ohs-foundation/ohs-player-reference-client-app.git
TERMINAL
$ cd ohs-player-reference-client-app
2
STEP 2 OF 3

Build the project

Run the complete build once. The implementation-guide code generator runs automatically before Kotlin compilation.

TERMINAL
$ ./gradlew build
✓
Expected resultBUILD SUCCESSFUL

The first build may take several minutes while Gradle downloads dependencies.

3
STEP 3 OF 3

Run a platform target

Choose a target to see its exact command. The desktop target is recommended for this quickstart.

TERMINAL
$ ./gradlew :ohs-player-reference-app:run
OHS Player
Patient register

3 sample records loaded

✓
Confirm the app is working

The patient register opens and displays three sample records without a configuration error.

Troubleshooting

Check these common setup problems before opening an issue.

Gradle cannot find Java 21+

Run java -version, then set JAVA_HOME to a JDK 21 installation and retry the build.

Android SDK location is missing+

Create local.properties in the repository root and set sdk.dir to your Android SDK path.

Generated configuration fails to compile+

Run ./gradlew generateIgCode --stacktrace and check the referenced FHIR Binary resources.
